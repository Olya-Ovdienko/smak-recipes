# Смак · особистий кулінарний записник

**Смак** — адаптивний сайт українською для збереження улюблених рецептів. Додавайте страви з фотографіями, інгредієнтами й покроковими інструкціями, знаходьте потрібне та готуйте з телефона або комп’ютера.

Поточна версія працює без бази даних: рецепти зберігаються в браузері. Проєкт має модульну структуру для подальшого розвитку та підключення серверного API.

## Можливості

- Створення, перегляд, редагування та видалення рецептів із підтвердженням.
- Фото з автоматичним зменшенням до 1200 px та стисненням у JPEG.
- Динамічні списки інгредієнтів і кроків приготування.
- Пошук за назвою, описом або інгредієнтом; фільтри за категоріями.
- Сортування за датою, часом приготування та назвою.
- Обране й автоматичний перерахунок інгредієнтів за кількістю порцій.
- Відмітки підготовлених інгредієнтів під час приготування.
- Друк рецепта з окремим оформленням для паперу.
- Експорт та імпорт резервної копії у форматі JSON.
- Шість позначених рецептів-прикладів під час першого запуску.

## Три сторінки

1. **Колекція — `index.html`.** Рецепти, пошук, категорії, сортування, обране та резервні копії.
2. **Редактор — `new.html`.** Створення рецепта; параметр `?id=…` відкриває запис для редагування.
3. **Рецепт — `recipe.html?id=…`.** Фото, опис, інгредієнти, порції, кроки та нотатки.

Обране доступне як режим колекції через `index.html?favorites=1`.

## Технології та адаптивність

- Семантичний HTML5.
- CSS3: Grid, Flexbox, CSS-змінні та медіазапити.
- JavaScript із нативними ES-модулями, без фреймворків.
- `localStorage` для даних, Canvas API для обробки завантажених фото.
- Node.js для локального статичного сервера та вбудованих тестів.

Верстка адаптована до телефона, планшета та десктопа. Основні точки зламу — 540, 760 та 1050 px. Є видимий фокус, підписи полів, керування з клавіатури, перехід до основного вмісту та підтримка `prefers-reduced-motion`.

## Локальний запуск

Потрібні **Node.js 20.11+** та Git для клонування. Сторонні npm-пакети встановлювати не потрібно.

```bash
git clone https://github.com/Olya-Ovdienko/smak-recipes.git
cd smak-recipes
npm start
```

Відкрийте [http://localhost:5173](http://localhost:5173). Для зупинки натисніть `Ctrl+C` у терміналі. Не відкривайте HTML подвійним кліком: ES-модулям потрібен HTTP-сервер.

Для перегляду з телефона в тій самій Wi-Fi мережі можна використати локальну IP-адресу комп’ютера та порт 5173, якщо доступ дозволений брандмауером. Сховище рецептів на телефоні буде окремим.

## Архітектура

Інтерфейс сторінок, робота з даними та спільні елементи розділені на модулі. `repository.js` — єдина точка доступу до рецептів: `list`, `get`, `upsert`, `remove`, `toggleFavorite`, `import`. Сторінки звертаються до репозиторію замість прямого запису в `localStorage`.

Рецепт містить ID, назву, опис, категорію, час, кількість порцій, фото, інгредієнти, кроки, нотатки та ознаку обраного. Нові записи отримують UUID. Ключ `smak.recipes.v1` містить версію сховища для майбутніх міграцій; процедура міграції ще не реалізована.

Кольори й типографіка винесені в CSS-змінні. Навігація, іконки, екранування користувацького тексту та повідомлення зібрані в `ui.js`.

Для підключення бекенду потрібно реалізувати асинхронний API-репозиторій, перевести виклики у сторінках на `await` і додати стани завантаження. Це збереже структуру інтерфейсу, але потребуватиме змін у модулях сторінок.

## Зберігання та резервні копії

Дані належать конкретному браузеру, пристрою та адресі сайту. Вони зберігаються після перезавантаження, але не синхронізуються між пристроями. Очищення даних браузера видаляє записи; приватний режим не підходить для постійного записника.

Використовуйте **«Експорт»** для завантаження JSON-копії та **«Імпорт»** для відновлення або перенесення. Імпорт об’єднує рецепти за ID: якщо ID збігається, імпортований запис замінює наявний. Некоректні записи відхиляються до збереження.

Обсяг `localStorage` обмежений браузером. Фото стискаються, але велика колекція може заповнити сховище. При помилці запису показується повідомлення, а форма залишається відкритою. Пошкоджені дані не замінюються прикладами автоматично.

Відмітки підготовлених інгредієнтів зберігаються лише в межах відкритої сторінки. Авторизації, спільного доступу та хмарної синхронізації в поточній версії немає.

## Перевірка

```bash
npm test
```

Сім тестів перевіряють початкові дані, створення й оновлення рецепта, обране, видалення, імпорт, відхилення пошкоджених даних і небезпечних URL фото, а також помилку переповнення сховища.

Під час розробки у браузері перевірено створення, збереження після перезавантаження, редагування, видалення з підтвердженням, пошук, категорії, обране та перерахунок порцій. Усі три сторінки перевірено на ширинах 375, 390, 768, 1024 та 1440 px без горизонтального переповнення. Цей браузерний сценарій був локальною перевіркою розробки й не входить до `npm test`.

## План подальших покращень

### 1. Зручність щоденного використання

- [ ] Автоматичне збереження та відновлення чернетки.
- [ ] Переставляння інгредієнтів і кроків.
- [ ] Власні категорії, теги та фільтри за складністю.
- [ ] Таймери для кроків і режим приготування з великим текстом.
- [ ] Узгодження одиниць вимірювання та форматів дробових кількостей.

### 2. Надійніше локальне зберігання

- [ ] Перенесення рецептів і фото до IndexedDB.
- [ ] Міграції схеми та версія формату експорту.
- [ ] Попередній перегляд імпорту й вибір між пропуском і заміною записів.
- [ ] Браузерні тести завантаження фото та резервних копій.
- [ ] PWA, service worker та локальні шрифти для повної роботи офлайн.

### 3. Сервер і синхронізація

- [ ] REST API та серверна валідація.
- [ ] База даних рецептів та окреме файлове сховище фотографій.
- [ ] Реєстрація, вхід і контроль доступу до рецептів за власником.
- [ ] Синхронізація між пристроями та обробка конфліктів змін.
- [ ] Перенесення локальних рецептів в особистий акаунт.

### 4. Нові можливості

- [ ] План харчування на тиждень.
- [ ] Список покупок із кількох рецептів.
- [ ] Посилання для спільного доступу до вибраних рецептів.
- [ ] Публічні добірки, оцінки та коментарі після впровадження авторизації.

Це план розвитку; позначені пункти ще не реалізовані.
